## 1. Что строим и зачем

Свой клиент Telegram для **Android** на основе официального открытого кода Telegram (как Novagram),
только для **рабочих аккаунтов компании**. Менеджеры работают в привычном Telegram со всеми возможностями
(быстрые ответы Telegram Business с кружками и геолокациями, стикеры, пересылка, поиск), но:

- **нельзя удалить** ни сообщения, ни чаты, нельзя очистить историю, включить автоудаление;
- нельзя выйти из аккаунта, сменить номер, открыть «Устройства», добавить другой аккаунт;
- удалённое **клиентом** остаётся в приложении с пометкой 🗑 (локальный архив, как Novagram);
- в каждом чате кнопка **💎** — карточка клиента из BILLZ (с нашего сервера);
- запрет скриншотов и записи экрана (`FLAG_SECURE`), как в приложении RADI Team.

Почему так решили (владелец, 24.11.2026):
- клиенты на **99% в Telegram**;
- в CRM-панели (бизнес-бот) ограничения Telegram: ответ только в окне 24 ч, нельзя писать первым,
  быстрые ответы Telegram Business боту недоступны (их нельзя прочитать через Bot API);
- своё приложение даёт всё «родное» сразу.

**CRM-панель остаётся** (уже сделана, `crm.py` + `bizwatch.py`): руководитель видит все чаты, удалённое,
заметки, задачи, отчёты. Бизнес-бот подключён к тем же аккаунтам → всё, что пишется из RADI Messenger,
тоже попадает в CRM. iPhone — **не сейчас** (оценка 4–8 недель, отложено).

## 2. Владелец и правила (кратко; подробно — CRM_MESSENGER.md, раздел 1)

- Отвечать по-русски, коротко, шаги нумерованным списком; перед большой работой — вопросы и «Да».
- PR → сразу squash-merge в `main` (разрешено владельцем), ветку сбросить на `origin/main`.
- **Секреты:** `api_id` / `api_hash` (my.telegram.org), ключ подписи APK, пароли аккаунтов — **никогда**
  в репозиторий и в чат. Сборка берёт их из переменных окружения / GitHub Secrets.
- Ключ подписи Android `*.keystore` уже в `.gitignore`. Для RADI Messenger — **отдельный** ключ.
- Код Telegram — лицензия **GPL-2.0**: исходники изменённого клиента держать открытыми для получателей
  (сотрудников). Свой форк держать в **отдельном репозитории** (например `radi-messenger`), не в `staff-bot`.

## 3. Условия, без которых защита не работает (сказать владельцу прямо)

1. **Рабочие номера (SIM) у владельца**, код входа приходит только ему.
2. **Облачный пароль (2FA)** на каждом рабочем аккаунте знает только владелец.
3. **Вход в RADI Messenger на телефоне менеджера делает владелец** — менеджер пароля не знает.
4. Иначе менеджер поставит обычный Telegram, войдёт в аккаунт и удалит всё там.
5. Бизнес-бот (`bizwatch`) остаётся подключённым как страховка — копия переписки на сервере.

## 4. Технический план

### 4.1 Основа
- Исходники: официальный Telegram для Android — `github.com/DrKLO/Telegram` (последний стабильный тег).
- Свой `api_id`/`api_hash`: владелец получает на my.telegram.org (вход по рабочему номеру) → GitHub Secrets
  или переменные окружения сборки. Показать владельцу шаги (Create application → App title «RADI Messenger»).
- `applicationId` своё (например `uz.radi.messenger`), имя «RADI Messenger», иконка — логотип RADI.
- В репозитории Telegram есть готовые нативные библиотеки (`TMessagesProj/jni` собирается NDK) — первым
  делом проверить, собирается ли проект в среде сессии (Android SDK: `/opt/android-sdk`, gradle `/opt/gradle`;
  для загрузки зависимостей нужны `dl.google.com`, maven-репозитории). Если локальная сборка невозможна —
  сборка через **GitHub Actions** (ubuntu runner, Android SDK/NDK) с артефактом APK.

### 4.2 Что убрать / заблокировать (найти в коде по местам вызова)
- удаление сообщений (меню сообщения, мультивыбор, `MessagesController.deleteMessages`);
- удаление/очистка чата, «Удалить и выйти», автоудаление (TTL), удаление контактов-переписок;
- выход из аккаунта, «Добавить аккаунт», смена номера, «Устройства» (завершение сеансов), удаление аккаунта;
- секретные чаты (нельзя контролировать) — скрыть создание;
- изменение настроек приватности/2FA (пароль только у владельца).
Принцип: убрать кнопки **и** заблокировать сам вызов в слое `MessagesController`/`ConnectionsManager`,
чтобы никакой путь (жест, меню, ссылка) не удалял.

### 4.3 Локальный архив удалённого
- Telegram при удалении собеседником присылает `updateDeleteMessages` — сообщение удаляется из локальной
  базы. Перехватить: вместо удаления пометить сообщение «🗑 удалено» и оставить показываться (как Novagram).

### 4.4 Кнопка 💎 BILLZ (сервер staff-bot)
Новый API в `webapp.py` для приложения (авторизация — токен устройства, выданный владельцем; по образцу
`appauth.py`, но отдельный тип токена «messenger»):
- `POST /api/msgr/client` {tg_id, username, phone?} → карточка клиента: имя BILLZ, уровень
  (`core.CLIENT_TIERS`), покупки, бонусы, долг (`erp.customer_card`, `erp.find_client`, `core.billz_base`),
  заметки CRM (`crm.info`), привязка клиента (как в CRM).
- `POST /api/msgr/link` {tg_id, billz_id} → ручная привязка.
В приложении: кнопка в шапке чата → нижний лист (BottomSheet) с карточкой; поиск/привязка, если не найден.
Значок уровня 🥉/🥈/🥇 в списке чатов — этап 2.

### 4.5 Распространение
- APK файлом (как `static/radi-team.apk`): ссылка в боте сотрудников; обновление поверх (тот же ключ).
- Без Google Play.

| 5 | Тест на одном менеджере, исправления | 3–5 дней |

| 6 | Значки уровня в списке, отметки покупок, связь с KPI | +1 неделя |

Поддержка: обновление под новые версии Telegram ~раз в 1–2 месяца (полдня).

## 6. Расходы (для владельца)

- SIM на рабочий номер: ~20–50 тыс. сум/мес каждый.
- Telegram Premium — нужен для бизнес-бота (CRM видит переписку): ~$3–6/мес на аккаунт.
- Сервер — без существенных изменений. Apple — не нужен (только Android).
- Рабочие Android-телефоны — по желанию (~$120–200 шт.).

## 7. Риски

- Сборка кода Telegram тяжёлая (размер, NDK) — может потребоваться GitHub Actions.
- Telegram может ограничить аккаунт, если клиентом спамят/массово пишут — не делать рассылок из приложения.
- Обновления Telegram ломают форк — закладывать время на поддержку.
- Если владелец передаст менеджеру пароль/код — защита теряет смысл.

---

## 8. Как проверять

- Каждый этап — APK на тестовый телефон владельца (рабочий аккаунт + второй аккаунт «клиента»).
- Чек-лист: нет пунктов удаления (сообщение, мультивыбор, чат, история), нет выхода/устройств,
  быстрые ответы Telegram Business работают (кружки, геолокации), 💎 открывает карточку,
  удалённое собеседником остаётся с 🗑, скриншот запрещён, сообщения видны в CRM-панели.

## 10. Ответы владельца (24.11.2026)

1. Android-телефоны для менеджеров владелец купит.
2. **Один рабочий аккаунт на всех**: тот же аккаунт входит на телефоны всех менеджеров (несколько сеансов).
3. Условия раздела 3 подтверждены: номер и 2FA только у владельца, вход делает он.
4. Нужны **все возможности Telegram** (секретные чаты, звонки, каналы, группы), но **включает/выключает
   только владелец**. Значит: набор разрешений на каждый телефон (устройство) хранится на сервере staff-bot
   (`/api/msgr/...`), приложение получает его при запуске и периодически; владелец меняет в кабинете/боте.
   Запреты удаления/выхода/устройств — всегда, их не выдают. Секретные чаты: архив 🗑 и CRM их не видят —
   владелец знает и решает сам.
5. Название «RADI Messenger», иконка — логотип RADI & CO.
6. Репозиторий `baleebaipro-jpg/radi-messenger` создан (приватный; GPL — исходники доступны сотрудникам по запросу).
